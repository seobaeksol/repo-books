# 기능 요구사항

## FR-001 책장 표시

**우선순위:** P0

- 사용자는 Apple Books형 책장 화면을 볼 수 있어야 한다.
- 데스크톱 책장은 좌측 sidebar와 최근 읽은 책, 내 책 grid로 구성되어야 한다.
- 모바일 책장은 단일 컬럼과 하단 navigation으로 구성되어야 한다.

**수용 기준**

- 책장에는 GitHub 주소 입력창이나 상단 전역 화면 전환 탭이 표시되지 않는다.
- 최근 읽은 책은 마지막 열람 순서로 표시된다.
- 내 책은 cover grid 형태로 표시된다.

## FR-002 새 책 만들기 진입

**우선순위:** P0

- 사용자는 데스크톱 sidebar 또는 모바일 하단 navigation에서 새 repo book 생성을 시작할 수 있어야 한다.
- 책장 본문과 상단 toolbar는 새 책 액션을 반복 노출하지 않는다.

**수용 기준**

- 데스크톱 sidebar의 `새 책 만들기`가 목차 생성 화면으로 이동한다.
- 모바일 하단 navigation의 `새 책`이 목차 생성 화면으로 이동한다.

## FR-003 책 생성 입력

**우선순위:** P0

- 사용자는 생성 화면에서 GitHub 저장소 URL을 입력할 수 있어야 한다.
- 사용자는 LM Studio 모델, 독자 수준, 책의 목적, 생성 깊이를 선택할 수 있어야 한다.
- 사용자는 책 생성에 추가로 반영할 커스텀 프롬프트를 입력할 수 있어야 한다.
- 시스템은 `lms ls --llm --variants --json`으로 로컬 LM Studio 모델 variant를 불러오고, 실패하면 직접 모델 ID 입력을 허용해야 한다.
- 시스템은 입력값을 검증하고 LM Studio 연결 여부를 진행 상태에 반영해야 한다.

**수용 기준**

- 필수 입력값이 없으면 목차 생성을 진행하지 않는다.
- 로컬 모델 목록을 불러오면 모델 입력 datalist에 표시하고, 수동 편집한 모델 값은 새로고침으로 덮어쓰지 않는다.
- 유효한 입력값이면 저장소 스캔부터 책 일관성 점검까지 단계별 상태를 표시한다.

## FR-004 저장소 분석

**우선순위:** P0

- 시스템은 저장소의 디렉토리 구조, README, 문서, 설정 파일, 엔트리 포인트, 주요 코드 파일을 분석해야 한다.
- 시스템은 manifest script/dependency, README heading, public symbol, route/API endpoint, config/env key, test target을 책 본문 재료로 추출해야 한다.
- 바이너리, 빌드 산출물, 의존성 캐시는 기본 제외해야 한다.
- 분석 결과는 repo book의 대단원 계획, 소단원 계획, 챕터 본문, 코드 앵커, 품질 검증에 사용되어야 한다.

**기본 제외 대상 예시**

- `.git`
- `node_modules`
- `dist`, `build`, `.next`, `.turbo`
- `.venv`, `venv`
- 바이너리 파일, 이미지, 대용량 압축 파일

## FR-005 책 구조와 본문 생성

**우선순위:** P0

- 생성기는 저장소를 일반 기술서 또는 강의 흐름에 맞게 대단원과 소단원으로 재구성해야 한다.
- 생성기는 선택한 LM Studio 모델이 로컬에 없으면 `lms get <model>` 방식으로 다운로드를 시도한 뒤 생성 단계를 계속해야 한다.
- 대단원/소단원 결정은 파일 트리의 단순 복제가 아니라 저장소 책임, 실행 흐름, 변경 지점의 학습 순서를 반영해야 한다.
- 각 챕터는 제목, 요약, 목표, 관련 파일, 예상 읽기 시간, 생성 상태, 핵심 질문, 책임, 흐름, 코드 앵커, evidence, glossary, recap을 포함해야 한다.
- 각 챕터 본문은 5-8개 section으로 구성하며, section별 본문은 실제 evidence path 또는 symbol/config/test 근거와 연결되어야 한다.
- LM Studio가 설정됐지만 section draft나 revision이 품질 기준을 통과하지 못하면 deterministic prose로 조용히 채우지 않고 해당 챕터를 `failed`로 표시해야 한다.

**수용 기준**

- 목차 생성 화면은 대단원과 챕터 목록을 표시한다.
- 생성 화면은 모델 준비, 저장소 분석, 대단원 설계, 소단원 설계, 근거 수집, 본문 생성, 챕터 수리, 책 일관성 점검 단계를 구분해 보여준다.
- background 생성 요청 직후에는 `generating` 상태의 placeholder book을 책장에 표시하고, 사용자가 해당 카드에서 생성 진행상황으로 돌아갈 수 있어야 한다.
- 생성 진행상황 화면은 경과 시간, 마지막 갱신 시간, 단계별 artifact 활동 로그, 챕터 job 상태를 표시해야 한다.
- 사용자는 생성된 목차에서 읽기 시작으로 이동할 수 있다.
- 실패한 챕터가 있으면 사용자는 해당 챕터 또는 전체 실패 챕터를 재시도할 수 있다.

## FR-006 책 읽기

**우선순위:** P0

- 사용자는 repo book을 ebook reader처럼 읽을 수 있어야 한다.
- 중앙 본문은 챕터 제목, 요약, 핵심 질문, 책임, 흐름, 본문 section, 코드 근거, evidence, glossary, recap, 체크포인트를 표시해야 한다.
- 관련 코드 블록은 읽기 흐름을 방해하지 않는 별도 코드 surface로 표시해야 한다.

**수용 기준**

- 현재 챕터가 책 본문 형태로 표시된다.
- 이전/다음 챕터 이동이 가능하다.
- 진행률이 하단 controls와 책장 카드에 반영된다.

## FR-007 목차 탐색

**우선순위:** P0

- 사용자는 책 읽기 화면에서 대단원과 챕터 목록을 볼 수 있어야 한다.
- 현재 챕터는 목차에서 시각적으로 구분되어야 한다.
- 모바일에서는 목차가 하단 sheet로 열려야 한다.

## FR-008 AI Margin Tutor

**우선순위:** P0

- 사용자는 책을 읽는 중 AI에게 질문할 수 있어야 한다.
- AI는 현재 책, 현재 챕터, 관련 파일, 이전 대화 맥락을 반영해 답변해야 한다.
- 데스크톱에서는 우측 inspector로, 모바일에서는 하단 sheet로 제공되어야 한다.

## FR-009 최근 읽은 책

**우선순위:** P0

- 사용자는 최근 읽은 책 목록을 볼 수 있어야 한다.
- 시스템은 마지막 열람 시각, 현재 챕터, 진행률을 저장하고 복원해야 한다.

## FR-010 포커스 모드

**우선순위:** P1

- 사용자는 읽기 화면에서 포커스 모드를 켤 수 있어야 한다.
- 포커스 모드에서는 목차와 AI 패널을 숨기고 본문을 확장해야 한다.
- 종료 시 이전 reading layout으로 돌아가야 한다.

## FR-011 컬렉션과 상태 필터

**우선순위:** P1

- 책장은 전체, 읽는 중, 생성 중, 초안 같은 상태 필터를 제공해야 한다.
- 필터는 내 책 grid에 적용되어야 한다.

## FR-012 저장과 복원

**우선순위:** P0

- 책, 목차, 챕터 진행률, 최근 읽은 순서, AI 대화, UI 상태는 저장되어야 한다.
- 새로고침 후에도 마지막 책장과 읽기 상태를 복원할 수 있어야 한다.
