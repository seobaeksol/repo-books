# Repo Book 구조와 체크포인트 요구사항

## Repo Book 구조

Repo Books의 산출물은 읽을 수 있는 기술서적이다. 저장소 분석 결과는 다음 구조로 정리한다.

```text
RepoBook
  Part 1
    Chapter 1.1
    Chapter 1.2
  Part 2
    Chapter 2.1
    Chapter 2.2
```

Part는 일반 기술서적의 대단원에 해당하고, Chapter는 실제로 읽는 기본 단위다. 화면과 데이터 명칭은 책, 파트, 챕터를 기준으로 통일한다.

## Part 요구사항

Part는 여러 챕터를 묶는 상위 읽기 단위다.

**필수 속성**

- Part ID
- 제목
- 요약
- 포함 챕터 목록
- 진행 상태
- 정렬 순서

**선택 속성**

- 핵심 저장소 영역
- 권장 선수 파트
- 예상 읽기 시간
- 생성 근거 파일 목록

## Chapter 요구사항

Chapter는 리더 화면에서 읽는 기본 단위다.

**필수 속성**

- Chapter ID
- Part ID
- 번호
- 제목
- 짧은 부제
- 읽기 목표
- 본문 섹션
- 관련 파일 목록
- 코드 앵커
- 체크포인트
- 진행 상태
- 예상 읽기 시간

**선택 속성**

- 여백 노트
- 용어 설명
- 추천 질문
- 다음에 읽을 챕터

## Chapter 본문 패턴

각 챕터는 책을 읽는 흐름으로 구성한다.

```text
챕터 제목
짧은 요약
이번 장에서 이해할 것
1. 문제 배경 또는 제품 흐름
2. 저장소 구조와 관련 파일
3. 핵심 코드 설명
4. 실행 흐름 또는 데이터 흐름
5. 정리와 체크포인트
```

파일 트리를 그대로 나열하지 않고, 독자가 기술서적을 읽듯 이해가 쌓이도록 순서를 만든다.

## 코드 앵커

코드 앵커는 본문 설명과 저장소 근거를 연결한다.

| 필드 | 설명 |
| --- | --- |
| filePath | 저장소 기준 파일 경로 |
| symbolName | 함수, 클래스, 컴포넌트, 설정 키 등 |
| lineHint | 선택적 줄 위치 또는 범위 힌트 |
| explanation | 본문에서 이 코드가 필요한 이유 |

앵커는 본문 읽기를 보조하는 근거다. 코드 전체를 과도하게 삽입하지 않고, 필요한 위치와 해석을 함께 제공한다.

## 체크포인트 요구사항

체크포인트는 시험이 아니라 독자가 이해를 확인하는 가벼운 표시다.

- 챕터당 2-5개를 권장한다.
- 체크박스, 짧은 메모, AI에게 질문하기 액션으로 표현할 수 있다.
- 완료하지 않아도 다음 챕터로 이동할 수 있다.
- 완료 여부는 최근 읽은 책과 챕터 진행률에 반영한다.
- 체크포인트 문구는 저장소 구조, 코드 흐름, 설계 의도, 변경 가능 지점을 확인하도록 작성한다.

## 진행 상태

| 상태 | 의미 |
| --- | --- |
| not_started | 아직 열람하지 않음 |
| in_progress | 읽는 중 |
| current | 현재 열려 있는 챕터 |
| completed | 사용자가 챕터를 완료로 표시했거나 끝까지 읽음 |
| generating | 책 또는 챕터를 생성 중 |
| draft | 생성된 목차를 읽기 전 상태 |
| failed | 생성 또는 갱신 실패 |

## 생성 품질 기준

- 목차는 일반적인 기술서적 또는 강의 흐름을 따른다.
- 첫 챕터는 저장소의 목적과 실행 맥락을 잡는다.
- 이후 챕터는 아키텍처, 핵심 도메인, 데이터 흐름, UI/인터페이스, 테스트/운영 순서처럼 이해가 깊어지는 방향으로 배치한다.
- 한 챕터는 너무 많은 파일을 다루지 않는다. 2-4개 핵심 파일을 중심으로 읽을 수 있어야 한다.
- 저장소에 없는 내용을 단정하지 않는다. 추론은 추론으로 표시하고 코드 앵커를 함께 제공한다.
